# 产品路书：cw3-insurance-headless-storefront

状态：2026-10-26 已换成 Hydrogen 2026.10 的 React Router 模板。本地开发需要 Node 22，地址是 http://localhost:5173/ 。客户账号仍要 `SHOP_ID`、`PUBLIC_CUSTOMER_ACCOUNT_API_CLIENT_ID` 和 HTTPS。

## 1. 这份文档做什么

这份路书回答三件事：这个项目是什么、为什么要做、第一版做到哪里为止。

它是后续编码的需求依据。李良荣明确说开始执行之后，才按下面的第一版改代码。

## 2. 产品是什么

这是给研发用的最小 Hydrogen 无头店铺。

研发用它检查各种插件接进 headless 店面之后是否正常。Captain Insurance 是这些插件之一，但不是这个店铺本身。店铺要先像一家普通店：能看商品、能加购、能进入 Shopify 结账页。插件在后续版本再单独接进来。

## 3. 为什么要做

插件需要一个稳定、干净的 headless 环境来验收。店铺自己保持最小，插件的问题才容易看出来。第一版先把这家普通店立起来，不把 Captain、折扣或 reward 混进基础路径。

## 4. 给谁用

使用者是研发，和李良荣一样，用这家店做插件集成测试。

不面向商家运营，也不面向真实购物顾客。

## 5. 第一版范围

2026-10-26 补充后的第一版，是一家尽可能像真实店铺的普通店：

1. 首页展示开发店里的商品。
2. 商品详情页，支持多变体选择后再加入购物车。
3. 集合页。
4. 搜索。
5. 客户账号。
6. 购物车可以查看和修改商品行，并进入 Shopify 托管结账页。结账仍用 `checkoutUrl`，不在本仓库自建。
7. 有一套完整的店面外观。模板自带的是 Hydrogen 默认视觉，不是某个指定品牌。若要换成指定品牌，开工前给出品牌资料。

仍然不做：

- 不集成 Captain Insurance。
- 不做 reward。
- 折扣码和礼品卡此前要求拿掉。官方骨架模板的购物车和 `/discount/:code` 会带上折扣。是否保留模板里的折扣，开工前再定。默认按「像真实店铺」保留模板折扣，拿掉 reward 和 Captain。

## 7. 可行性

这些店面功能官方模板已经实现，不必从零写。

- 本仓库的 Hydrogen 版本是 `2026.1.1`，来源是 Skeleton。Shopify 在 `2026-01` 标签里的同一套 Skeleton 已包含商品详情与变体、集合列表和集合页、搜索、客户账号（登录、资料、地址、订单）、购物车和结账，另外还有博客、页面和政策页。当前仓库只留下首页和购物车，其余路由被拿掉了，搜索组件和变体链接工具还留在代码里。
- 2026 年 10 月的新 Hydrogen 另有一套 React Router 模板，也自带首页、集合、商品、搜索、购物车、客户账号、分析和同意条。它的目录结构和本仓库不同，不能把文件直接贴进来。本仓库继续用 `2026.1.1` 时，应对齐 Skeleton，而不是换到那套新模板。
- 客户账号需要 Customer Account API 的环境变量。本地登录还要 HTTPS。模板带了页面，店铺侧仍要配好账号。
- 结账能否打开，仍取决于开发店已链接，以及 `PUBLIC_CHECKOUT_DOMAIN` 有效。
- 不依赖 `cw3-insurance-captain-web-client-headless`。

## 8. 怎样算第一版做成

研发打开店铺后可以：

1. 从首页或集合进入商品详情，选中一个变体再加入购物车。
2. 搜索到商品。
3. 登录客户账号并看到账号页。
4. 从购物车进入 Shopify checkout。
5. 页面结构看起来像一家完整网店，而不是功能演示。

页面上不出现 Captain 保障开关，也不出现 reward。

## 9. 开工前仍可改的默认

不回复就按这些默认做：

1. 从与本仓库同代的 Hydrogen Skeleton 恢复商品、集合、搜索和客户账号，不换到 2026 年 10 月的新模板。
2. 保留模板自带的店面外观。没有单独的品牌稿时，不另做一套视觉。
3. 保留模板里的折扣能力。reward 不新增。
4. 删除未引用的 `CaptainInsuranceDemo.tsx`。
